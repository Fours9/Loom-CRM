# Старт для Адміна (пілот)

Короткий сценарій для внутрішнього пілоту LoomCRM. Не замінює living docs.

## Ролі

| Роль | Що дати в пілоті |
| --- | --- |
| Адміністратор | люди, доступи, анкети (lifecycle), proposals |
| Менеджер | команда в скоупі, призначення анкет (Assign) |
| Працівник | власна анкета, календар/заявки, «Про себе» |

## Довідка «?»

У правій верхній шапці (shell) є **?**. Меню:

- **Основне** — тур оболонки (☰ навігація, тема, сповіщення); працює і на телефоні при закритому drawer.
- **Поточна сторінка** — spotlight-тур для покритого екрана / вкладки / підвкладки (Головна, Працівники, Робочий календар, Посади, Налаштування, Анкети). Кроки пояснюють **дії** (кнопки, фільтри, панелі), а не «область екрана». «Статистика» лишається «· незабаром».

У **модалці** (форма посади, ролі, призначення, завантаження документів тощо) окрема **?** біля заголовка форми — основний і гарантований вхід у підказку полів. Перший Esc закриває лише підказку (форма лишається); Tab лишається в панелі підказки.

На заповненні анкети shell сховано: **?** у fill topbar пропонує лише тур цієї анкети (без «Основне»). Локальних «?» біля H1 звичайних сторінок немає — лише Shell/fill + modal titlebar.

Життєвий цикл (єдиний текст у коді: `questionnaire-help.definition.ts`):

> Відкріплення не видаляє анкету. Відкріплену анкету можна знову закріпити за доступним працівником, у тому числі за іншим. Заповнені відповіді зберігаються; після наступного надсилання пропозиції змін формуються для поточного працівника.

Після надсилання зміни зʼявляються в «Запропоновані зміни» і застосовуються лише після прийняття.

Реєстрація турів — `registerAppHelp()` при старті додатку (pure leaf modules: home/people/absences/positions/settings/questionnaires + `app.main`). Тексти турів — у `*-help.definition.ts`; register лише підключає bundle. Не залежить від візиту lazy-маршрутів і не тягне feature components/services/facades у bootstrap.

## Рекомендований сценарій пілоту

1. Створити / призначити анкету працівнику.
2. Заповнити й надіслати → прийняти proposals у картці.
3. Відкріпити → знову закріпити (тому ж або іншому) — перевірити, що відповіді лишились.
4. Робочий календар: одна заявка на відсутність.
